# 前端视觉与交互设计指南

状态：建议默认值。若产品已有品牌规范或设计系统，以获批准版本为准；首次落地前需项目负责人确认主题 token。

## 1. 设计定位
面向业务管理、运营、流程和数据密集型工作的现代企业级 B/S 系统。关键词：清晰、稳健、克制、易扫描、反馈明确、一致性高。页面第一目标是帮助用户正确高效完成业务，而非装饰。

## 2. 建议视觉 tokens
以下数值仅为默认提案，批准后集中写入主题文件，页面不可散落硬编码：

```css
:root {
  --color-primary: #2563EB;
  --color-primary-hover: #1D4ED8;
  --color-text: #111827;
  --color-text-secondary: #4B5563;
  --color-text-muted: #6B7280;
  --color-border: #E5E7EB;
  --color-border-strong: #D1D5DB;
  --color-background: #F8FAFC;
  --color-surface: #FFFFFF;
  --color-success: #15803D;
  --color-warning: #B45309;
  --color-danger: #B91C1C;
  --color-info: #0369A1;
  --radius-sm: 4px;
  --radius-md: 6px;
  --radius-lg: 8px;
  --shadow-popover: 0 8px 24px rgb(15 23 42 / 12%);
}
```

颜色不能作为唯一状态表达方式，需配合文本、图标或其他语义提示。

## 3. 字体、间距、形状
- 使用系统中文无衬线字体栈；不引入未经批准的远程字体依赖。
- 正文建议 14px，辅助文本 12–13px；重要说明不得过小。页面标题 20–24px，区块标题 16–18px，最终按主题统一。
- 使用 4px 基准间距刻度：4、8、12、16、20、24、32px。
- 圆角以 4–8px 为主；阴影仅用于需要层级的浮层/弹窗；分割线只在帮助分组时使用。
- 不用满屏粗体、过多卡片、重阴影和大圆角制造层级。

## 4. 页面布局
### 管理后台
- 常见结构为侧边导航、顶部栏和主内容区；已有项目沿用现有布局。
- 主内容区需有明确页面标题、必要的面包屑/说明、主操作和内容区。
- 每个视图一般只有一个最突出主操作；不要任意改变导航宽度、标题位置和页边距。

### 列表页
默认顺序：标题与主操作 → 搜索/筛选 → 必要的批量操作 → 表格/列表 → 分页及结果数量。次要筛选可分组或折叠，筛选/重置/应用行为要明确。

### 详情页与表单页
- 详情页先呈现身份、状态和关键字段，再呈现辅助信息；审计字段格式统一。
- 表单按业务分组；标签、必填、帮助文案和校验错误明确。
- 区分保存、提交、审批、取消；长表单按步骤或分组组织。
- 编辑场景明确初始值、取消和未保存离开提示。

## 5. 表格与数据密度
- 表头、行高、列宽、对齐规则一致；文本通常左对齐，数值/金额按项目统一规则。
- 状态使用统一语义色和文本标签。
- 大数据量使用服务端分页、筛选和排序；禁止前端全量拉取后再过滤。
- 长文本可以截断，但必须可查看完整内容。
- 低频操作放在更多菜单；批量操作显示影响范围，破坏性操作需要确认。

## 6. 颜色、图标、动效
- 禁止没有设计依据的大面积渐变、玻璃拟态、霓虹色、粒子背景、重阴影和无意义动效。
- 禁止 Emoji 充当正式业务图标；复用批准图标库。
- 反馈应明确：loading、成功、失败和下一步操作清晰。
- 破坏性动作说明后果；只对必要风险操作做二次确认。
- 动效用于状态反馈且保持克制，尊重减少动态效果偏好。

## 7. 响应式与可访问性
- 建议至少检查 1440、1024、768、390 像素宽度下的布局。
- 窄屏下不能遮挡关键操作或造成不可控的整页横向滚动；复杂表格可内部横向滚动。
- 使用语义化 HTML；标签正确关联输入控件；键盘可操作且焦点可见。
- 对比度目标为 WCAG 2.1 AA；错误不能只用颜色表达。
- 图标按钮提供可访问名称；弹窗正确管理焦点。

## 8. 图表与仪表板
- 图表服务于明确业务问题；必须有标题、时间范围、单位、必要图例和空数据状态。
- 不只靠颜色区分系列；关键指标注明口径、周期或更新时间（适用时）。
- 不为了填充空间添加没有业务含义的图表。

## 9. CSS 实施
- 主题值集中在 CSS variables/design tokens；禁止页面随意散落颜色、间距、圆角。
- 优先复用统一基础组件；不得多套风格并存。
- CSS 作用范围要可控；避免全局选择器污染组件库或其他页面。
- `!important` 不作为常规修复方式；不得靠大量负 margin 或 absolute positioning 叠补布局问题。
